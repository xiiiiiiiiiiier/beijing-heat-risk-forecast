# 北京城六区 ECMWF IFS 预报采样格点

生成日期：2026-09-14。范围：东城区（110101）、西城区（110102）、朝阳区（110105）、丰台区（110106）、石景山区（110107）、海淀区（110108）。本文件仅确定空间边界、采样点和面积权重，不涉及气象风险计算。

## 边界来源与坐标

- 区级矢量边界来自 [pamaforce/geojson 的北京市 WGS84 文件](https://github.com/pamaforce/geojson/blob/main/geojson_wgs84/100000/110000/110000.json)。该仓库说明：原始数据于 2024-04-07 从阿里云 DataV GeoAtlas 获取，源于高德开放平台的 GCJ-02 数据，再转换为 WGS84。它是**第三方转换数据，不是北京市官方法定边界矢量**。
- [北京市民政局 2025 版行政区域界线基础地理底图](https://mzj.beijing.gov.cn/col/col11010/index.html)用于核对六区范围及名称；官方发布的是地图，不是本次计算使用的可直接叠加矢量边界。
- 按行政区划代码抽取六区并合并为一个有效联合几何；由于源数据中的朝阳区有一个分离部分，结果在 GeoJSON 中按规范表示为单个 `MultiPolygon` 要素（两个组成面），没有人为填补中间的非六区区域。交付坐标为 WGS84 经纬度（EPSG:4326）。第三方边界与官方法定界线可能有差异，且 GCJ-02 → WGS84 转换也存在精度限制。用于正式对外发布的行政边界时，应取得官方许可的矢量界线替换并重算权重。

## 模式格点与 API 映射

- 固定使用 Open-Meteo `/v1/ecmwf` 的 `models=ecmwf_ifs`（IFS HRES，约 9 km），并设置 `cell_selection=nearest`、`elevation=nan`。**不使用** `ecmwf_ifs025`（0.25°）。[Open-Meteo ECMWF 文档](https://open-meteo.com/en/docs/ecmwf-api)说明两者是不同分辨率的产品，API 返回坐标是所用天气网格中心。
- 按 [ECMWF O1280 八面体约化高斯网格定义](https://confluence.ecmwf.int/pages/viewpage.action?pageId=47300860)生成实际格点中心：南北各 1280 条高斯纬线，纬度取 2560 阶勒让德多项式根的反正弦；每纬线从极地侧第 1 行 20 个经度点开始，逐行增加 4 个，经度从 0° 起按 `360 / n` 分布。这些点**不是任意等间距采样点**。
- 对最终 30 个有效中心逐一通过多点 API 请求核对返回坐标。最大偏差约 1.01 米，属于返回坐标的小数位舍入量级；返回坐标共 30 个唯一值，无重复网格点。将来若 API 更改格点选择或模型，必须重新核对并重算。

## 面积权重

- 在以北京为中心的 WGS84 Lambert 方位等面积投影（`+proj=laea +lat_0=39.9 +lon_0=116.4 +datum=WGS84 +units=m`）下计算面积。
- 用附近全部 O1280 格点中心在该投影下构造最近中心 Voronoi 代表单元；这些单元是用于空间加权的**最近格点服务区近似**，并非 ECMWF 发布的原生单元边界。逐一与六区联合边界相交，保留面积大于 1 平方米的单元。某些有效格点中心位于六区边界之外，但其代表单元与六区相交，因此保留。
- `intersect_area_km2` 为相交面积；`area_weight = intersect_area_km2 / 六区总相交面积`。六区联合面积与相交面积合计均为约 **1376.496 km²**，权重和 **1.0000000000**。这与北京市规划口径“中心城区约 1378 平方公里”数量级一致，但两者并非同一套边界测量成果。[规划口径](https://www.beijing.gov.cn/zhengce/zwmcxb/mczl/csgh/sdhxgn/202302/t20230214_2916740.html)
- 与既有 ERA5-Land 方法同属“格点代表区域和目标区域相交面积加权”，但这里使用的是 IFS O1280 约 9 km 预报格点，**不能沿用 ERA5-Land 的格点或权重**。

## 文件与使用约束

- `six_districts_union.geojson`：六区联合面。
- `forecast_points.csv`：每行一个有效 IFS 格点。实际取数应使用 `latitude`、`longitude`，并保持 `models=ecmwf_ifs&cell_selection=nearest&elevation=nan`；`api_latitude` 和 `api_longitude` 是本次核验返回值。
- `forecast_grid_spatial_check.png`：主体区域、分区边界、有效代表单元和格点中心的空间检查图。按展示要求，朝阳区与主体分离的组成面及其对应格点仅在图中隐藏；GeoJSON、CSV 和权重仍保留完整六区范围。

若以后从 `ecmwf_ifs` 改为 0.25°、其他模式或 Open-Meteo 的默认 `best_match`，此 CSV 的权重不再适用。
